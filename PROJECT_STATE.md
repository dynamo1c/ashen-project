- [x] **Copilot chat/voice agent crash fix (July 2026):** the AI Query Agent was returning a hard "Error: Failed to connect to the database query agent" for every query, even under `catalyst serve` — reported with a terminal trace showing `catalyst.initialize(req)` throwing `CatalystAppError: invalid_project_details / Failed to parse object` inside `handleQueryRequest`. Root cause: the SDK's `initialize()` needs `x-zc-projectid`/`x-zc-project-key`/`x-zc-environment` request headers that weren't present on this request (a local dev/emulation limitation, not something in our control), and — unlike every other analytics route in this file, which wraps `catalyst.initialize()` in its own try/catch with a mock fallback — `handleQueryRequest` called it unguarded as its very first line, so the whole endpoint hard-failed before the (already-resilient) Cerebras/Gemini tool-calling loop ever got a chance to run.
  - Fix in `functions/ashen_api/index.js`: wrapped the `catalyst.initialize()` call in its own try/catch (`catalystApp = null` on failure, matching the `[Notice]` logging convention used everywhere else), and added an early graceful-degradation return for the rule-based fallback path (which makes raw unguarded `catalystApp.zcql()` calls) when `catalystApp` is null.
  - Confirmed the Cerebras/Gemini agent path needed *no* changes — `executeAgentTool()`'s outer try/catch already converts a null-`catalystApp` crash from any tool (`get_fir_stats`, `trace_accomplices`, `file_fir`, etc.) into a `{error: "..."}` string the LLM sees and reasons around, so the agent now answers coherently even with the datastore unreachable (e.g. acknowledging the query failed and giving a caveated estimate) instead of crashing.
  - Verified live: both `/api/chat/query` and `/api/copilot/query` now return 200 with a full reasoning trace instead of 500, and the actual chat panel renders the response correctly end-to-end (confirmed via a real Enter-key send, not just a raw curl check). Response time is ~30-45s for a full 5-turn tool-calling loop against Cerebras — that's pre-existing agent-loop latency (documented 5-turn cap in CLAUDE.md), not something this fix changed or something broken.
